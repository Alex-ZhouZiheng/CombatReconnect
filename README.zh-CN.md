# CombatReconnect

面向《Slay the Spire 2》的 C# 模组，提供战斗中断线重连、确定性输入回放和多人投票回滚。

[English README](README.md) · [构建与测试](docs/TESTING.md) · [双端测试矩阵](docs/MULTIPLAYER_TEST_MATRIX.md)

作者：**Ziheng Zhou**。当前源码版本为 **0.6.32**，协议为 **63-monster-runtime-state**。项目仍处于实验阶段；已有多人协议实现，但完整可靠性需要主机和客户端的配对实测日志确认，不能用编译通过或工具自检代替。

## 功能

- 非主机玩家在战斗中断线后，主机保留座位并暂停，客户端通过 Join Friend 或 Steam 邀请返回。
- 按 **F4** 或点击可拖动的回滚按钮恢复当前玩家回合；右键按钮可选择历史回合，默认保留十个。
- 多人回滚需其他参与者在 20 秒内同意；主机协调安全边界、恢复、回放、验证和最终提交。
- 回滚失败时恢复操作前的安全快照，验证恢复结果后再继续。
- 单人战斗完成至少一整轮后，按 **F6** 执行消息编解码、回放和安全恢复集成自检。

双方需要一致的游戏及模组版本。STS2-RitsuLib 由 Steam Workshop 安装和管理，不随本项目复制分发。

## 工程设计

**确定性回放。** 恢复锚点后逐个执行主机已确认的输入，自动应用记录的选择；每台机器保持真实本地身份，操作保持原记录所有者。回放还需处理异步动作、动态生物、卡牌对象映射和重复自动 Ready 事件。

**多人事务。** 投票通过后先冻结输入、排空动作并验证边界，再恢复与回放；只有双端状态和计数器通过验证才提交。失败路径保留安全快照并验证恢复结果。

**隐藏随机状态诊断。** 合成重连进入战斗时曾多追加一条地图历史，使当前战斗校验通过，但影响由楼层数参与播种的遭遇私有 RNG，导致下场战斗怪物不同。修复将各章节地图历史数量纳入扩展状态和指纹，只删除满足严格条件的合成条目，并重新核对总楼层数。双端跨战斗回归仍需实测证据。

**可复现诊断。** 提供构建、PCK/ZIP 打包、安装核验、双端日志会话、错误识别和九场景回归矩阵。工具测试使用合成日志，不代表真实多人游戏验证通过。

完整架构图和源码导航见 [英文 README](README.md)。项目未宣称未经测量的性能提升或用户规模。

## 构建与验证

需要 .NET 9 SDK、本地游戏安装，以及 NuGet 依赖 STS2.RitsuLib 0.4.59。游戏程序集不包含在仓库中。

```bash
git clone https://github.com/Alex-ZhouZiheng/CombatReconnect.git
cd CombatReconnect
dotnet build -c Release -p:STS2GameDir="/你的游戏安装路径/Slay the Spire 2"
```

macOS 工具自检：

```bash
tools/test-tooling.sh
```

发布、安装和实际双端测试步骤见 [构建与测试指南](docs/TESTING.md)。脚本面向 macOS/zsh；项目文件也提供 Windows 游戏程序集路径，尚不能据此认定跨平台运行已验证。

2026-11-11 仓库整理检查：工具回归自检通过；Release 构建因配置路径缺少游戏程序集而未能完成，因此本次未验证当前源码的编译、游戏内运行或双端行为。

## 限制与来源

尚不支持主机迁移和游戏结束后回滚；首个安全回合锚点前的断线不能热重连。重连校验不一致时会中止并保持暂停。项目依赖抢先体验版游戏内部 API，游戏更新后需要重新检查兼容性。

CombatReconnect 从 [个人 STS2 模组工作区](https://github.com/Alex-ZhouZiheng/SLS2Mods) 提取；该工作区 fork 自 [luojiesi/SLS2Mods](https://github.com/luojiesi/SLS2Mods)。本仓库只展示 CombatReconnect，不将其他模组或第三方库归为本项目成果。使用游戏原生回放接口、Harmony、Godot 和 RitsuLib，不依赖或分发 Rewind 的代码与资源。

仓库不包含游戏程序集、存档、真实游戏日志或第三方库源码。它是非官方项目；游戏及第三方依赖各自保留原有权利，本仓库未另行授予开源许可证。
